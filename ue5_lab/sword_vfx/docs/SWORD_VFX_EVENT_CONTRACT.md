## 0. Which side owns what

| Concern | Owner | Where it lives |
|---|---|---|
| WHEN an instant happens | **Godot — Sword / Character line** | `godot/scripts/combat/sword_basic.gd`, `iaido_director.gd`, `resources/tuning/IaidoTuning.tres` |
| HOW FAR / HOW BIG | **Godot — Sword / Character line** | same files, `*_scale` / `reach_*` / `SCAR_*` / `ARC_*` constants |
| WHAT IT LOOKS LIKE IN PRODUCTION | **this line** | `ue5_lab/sword_vfx/` |
| The sound of a beat | AUDIO line | `AU_*` in `sword_basic.gd` |

**The rule this document exists to enforce:** a Niagara system never derives a
time from its own Lifetime, Delay or curve. Every instant arrives as an event
with an explicit `t`, and every magnitude arrives as a `User.*` value. A graph
that guesses is a graph that goes silently wrong the first time the draw is
retuned.

Every `t` below was **read out of the shipping Godot source**, not estimated.
Where Godot does not yet have the beat, this document says so instead of
inventing a number — see §5.

---

## 1. There are TWO event sources, and they are not interchangeable

Godot does not have one event bus. It has two, and the split is deliberate
(`sword_combat_vfx.gd:270`):

1. **The move clock** — `SwordMove.events`, a list of `{t, id}` fired by
   `_tick_move_events()`. These are instants on the move's own clock, so a draw
   bonus that shortens the wind-up by 22% moves the cut with it.
   *Safe to play from a clock. Not safe to build geometry from.*

2. **The reach signal** — `SwordReach.trace_resolved` / `arc_resolved`, emitted
   **when a cut actually resolved**, carrying the tested window. Godot's own
   comment says why geometry must come from here rather than from the clock:
   taking it from the clock makes "the window that was tested" and "the window
   that produced the mark" two different objects that agree only by luck.

**Consequence for UE5:** the contact / hit family is bound to source 2. The
presentation family is bound to source 1. A1's `EV_SWORD_A1_HIT` therefore has no
`t` — it fires when the trace resolves, which is a frame, not a timestamp.

---

## 2. Naming

UE5 event names are the brief's `EV_SWORD_*` / `EV_IAIDO_*`. Godot's raw ids are
kept beside them because **Godot's raw ids are ambiguous across moves** — the
same literal `A1_SHEATH_TOUCH` is fired by both `sb_a1` and `sb_equip`:

```
sword_basic.gd:446   {"t": 0.00, "id": EV_SHEATH_TOUCH}   # inside a1()
sword_basic.gd:928   {"t": EQUIP_E0, "id": EV_SHEATH_TOUCH}  # inside equip()
```

So a UE5 mapper **must know which move it is in**. The contract carries
`(move_id, godot_event_id)` as the key, never the raw id alone.

## 5. A3 — 小居合领域 · 三次划痕 · `sb_a3` ⭐ the beat the brief calls the hero

Timing (`sword_basic.gd:171`): `A3_RETURN_HOME 0.10 / HOLD_END 0.16 / CUT1 0.16 /
CUT2 0.34 / CUT3 0.54 / RESOLVE 0.68 / SETTLE 0.78 / TOTAL 1.00`

| UE5 event | Godot source (`sb_a3`) | t (s) | Meaning | Consumes |
|---|---|---|---|---|
| `EV_SWORD_A3_SHEATHE` | `A3_SHEATHE` | 0.100 | blade returns to the mouth, home in the fist | `NS_SW_Core_EdgeTrail` |
| `EV_SWORD_A3_DOMAIN_BEGIN` | `A3_DOMAIN_START` | 0.120 | the micro-domain opens (`domain_from 0.08`) | lens + `NS_SW_Core_PurpleMotes` |
| `EV_SWORD_A3_CUT_1` | `A3_CUT_1` | 0.160 | mark 1 — `/` | `NS_SW_Core_SpatialScar` instance 1 |
| `EV_SWORD_A3_CUT_2` | `A3_CUT_2` | 0.340 | mark 2 — `\` | instance 2 |
| `EV_SWORD_A3_CUT_3` | `A3_CUT_3` | 0.540 | mark 3 — shallow horizontal | instance 3 |
| `EV_SWORD_A3_DOMAIN_END` | `A3_DOMAIN_END` | 0.680 | domain releases over the first cut | lens restores; scars keep their own life |
| `EV_SWORD_A3_HIT` | *(source 2)* `SwordReach.trace_resolved` | on resolve | a mark found a body | `NS_SW_Core_Hit` at the mark's midpoint |

**The three marks are already specified as data.** `move.traces`:

| # | t | angle | reach | damage weight | lens offset (tangent units) |
|---|---|---|---|---|---|
| 1 | 0.16 | **+38.0°** | 14.0 m | 0.30 | (−0.10, −0.06) |
| 2 | 0.34 | **−34.0°** | 16.0 m | 0.30 | (+0.10, −0.02) |
| 3 | 0.54 | **+4.0°** | 18.0 m | 0.40 | (0.00, +0.03) |

Godot's comment on the offsets is the whole reason mark separation works, and
UE5 must preserve it:

> `offset` moves each mark off the exact centre of the lens … three cuts that
> intersect at the same place read as a starburst, which is a UI glyph rather
> than a sword technique.

So the UE5 `EV_SWORD_A3_CUT_n` payload must carry **angle, reach and offset** —
not just the event. Otherwise §20's "three scars must still separate into three"
cannot be satisfied, it can only be hoped for.

**A3 magnitudes to inherit:**
* `SCAR_OPEN 0.045` — the mark widens once as it appears. A mark that pops in at
  full width reads as a decal.
* `SCAR_HOLD 0.46` — held so cut 1 is still on screen when cut 3 arrives. Godot:
  "a mark that has already faded is one mark seen three times."
* `SCAR_FADE 0.55`.
* `SCAR_EDGE_WIDTH 0.034 m` — and the reasoning is a UE5-relevant measurement:
  0.020 m was **sub-pixel at 720p at 16 m**, which is why pass 05's three cuts
  washed into haze. 0.034 is ~2.5 px there and still a line, not a band.
  **In UE5 this becomes a world-space width that must be re-checked against the
  camera at 14–18 m, not a texture pixel count.**
* `trace_half_thick_tan 0.11` ≈ ±6°.
* Brief §11 wants draw-on 20–60 ms / hold 120–250 ms / fade ~100 ms. Godot's
  hold is 460 ms — **longer, on purpose**, and the reason is the countability
  argument above. §11's numbers are a floor, not a ceiling; the Godot value wins
  because §1 says the Godot line owns feel and it has a stated reason.

## 6. A4 — 周身优弧横斩 · `sb_a4`

Timing: `startup 0.12 / strike 0.20 / follow 0.11 / recovery 0.23` → **0.660 s**
`reach_mode = arc` · **`reach_radius 4.2 m`** · **arc −140.0° → +130.0° = 270°** · `arc_slices 6` · `trail_width_scale 1.75` · `hitstop 0.055` · `fov_kick 2.2`

| UE5 event | Godot source (`sb_a4`) | t (s) | Meaning | Consumes |
|---|---|---|---|---|
| `EV_SWORD_A4_ARC_BEGIN` | `A4_ARC_START` | 0.120 | the arc starts forming, live, with the blade | **`NS_SW_Core_MajorArc`** — `ArcStart −140°`, `ArcEnd +130°` |
| `EV_SWORD_A4_ACTIVE` | `A4_ACTIVE` | 0.120 | the tested window opens | trail + arc head |
| `EV_SWORD_A4_HIT` | *(source 2)* `SwordReach.arc_resolved` | per slice | slice `n` of 6 found a body | `NS_SW_Core_Hit` at the slice's midpoint |
| `EV_SWORD_A4_ARC_END` | `A4_ARC_END` | 0.320 | the sweep is complete | arc begins `ARC_LIFE 0.55 s` fade |

**§12's "the arc must form live so the player sees START → SWEEP → END" is a
hard requirement and it dictates the implementation:** the arc is drawn on along
its own sweep, driven by the A4 timing, **not** scaled up from the centre. That
is exactly why `SM_SW_ArcSheet` carries the sweep on **U** — a U wipe along the
sweep is a draw-on; a uniform scale would read as an expanding ring, which is the
shockwave §12 forbids.

**A4 magnitudes to inherit:**
* `ARC_BAND 0.13 m` — and pass 05's failure is recorded: **0.32 m was a wall**.
  At a 3–5 m radius, 32 cm subtends ~4.6° ≈ 100 px at 720p, and a 100 px tall
  translucent band wrapped 270° around the viewer reads as *a sheet of water
  standing in the air*, not as a blade going past. 0.13 m is 1.9° ≈ 41 px.
  **This is the single most transferable number in the file for UE5.**
* `ARC_LIFT 0.22`, `ARC_BREATH 0.055` — §14's "略有高度变化，不要绝对数学圆".
* `ARC_LIFE 0.55`, `ARC_SUBDIV 5`, 6 slices.
* Godot's note on head fade is the read: "a cut that is still there is not a cut."

**Magic A4 (§21):** same geometry, same timing. The extra is an **incomplete**
wake behind the arc — `NS_SW_Core_MajorArc/E_ArcMist`, driven by `User.MistCount`.
It must never close into a ring even at maximum. Because the mist emitter's count
is a `User.*` int, "incomplete" is a profile value, not a graph difference.

NE_DRAW_FULL 1.40 / NE_SETTLE 0.35 / NE_TOTAL := NE_DRAW_FULL + NE_SETTLE = 1.75`
`NE_PARTIAL_DRAW = 0.160 m` · `SAYA_PUSH = 0.048 m`

| *(no VFX obligation)* | `EQUIP_CARRY` | 0.350 | the assembly is up and still | — |
| `EV_SWORD_EQUIP_PARTIAL_DRAW` | `DRAW` | **0.750** | **`NE_PARTIAL_DRAW = 0.160 m` of blade is exposed** | `NS_SW_Core_Glint` armed; Magic: a thread of black mist at the saya mouth |
| `EV_SWORD_EQUIP_GLINT` | `EQUIP_GLINT` | **0.950** | Beat 3: the cold glint begins | **`NS_SW_Core_Glint`** — the scan along the exposed blade |
| `EV_SWORD_EQUIP_FULL_DRAW` | `SAYA_PUSH` | **1.070** | Beat 4: the rest of the extraction; the off hand drives the saya **the other way** | glint fades; `NS_SW_Core_EdgeTrail` engages |
| `EV_SWORD_EQUIP_END` | `EQUIP_SEAT` | **1.400** | blade home in stance, sword right, saya left | all equip VFX → 0 |

**Why 0.160 m matters and must not be changed downstream (§7):** Godot's comment
is explicit — *"a glint needs a surface to run along, and at 0.16 m there is
160 mm of it."* The glint's 80–160 ms is only legible because there is 160 mm of
blade to scan. If UE5 briefly shows less blade, the glint becomes a flash.

**The glint is 120 ms here** (`NE_HOLD_END 0.95 → NE_GLINT_END 1.07`), which sits
inside §7's 80–160 ms band. **Timing is taken from this event pair, never from a
Lifetime in the graph.**

**The off hand is not decoration (§21).** `saya_push()` returns "how hard the
off hand is working" as a deterministic function of the move and its own clock.
The Mist thread at Beat 2 and the saya's counter-move at Beat 4 are what make it
a draw rather than one object sliding — Godot's own words.

## 8. INSPECT — **no Godot timing exists.** Reported, not invented.

The brief lists `EV_SWORD_INSPECT_BEGIN`, `EV_SWORD_INSPECT_GLINT`,
`EV_SWORD_INSPECT_ALIGN_SAYA`, `EV_SWORD_INSPECT_END`.

**Godot has no inspect move.** Verified:

```
$ grep -rn "inspect\|INSPECT" godot/scripts/ --include=*.gd
  → only unrelated hits (a character asset inspector, an NPC action named
    "inspect", a comment in iaido_director.gd)
$ grep -n "const EQUIP\|func moves" sword_basic.gd
  → A1 A2 A3 A4 EQUIP.  moves() returns [a1(), a2(), a3(), a4()]
```

There is no `sb_inspect`, no `EV_INSPECT_*`, and no inspect timing to inherit.

Per §1 this line **does not get to invent the timing** — Godot owns "what it
should look and feel like". So:

* **`NS_SW_Core_Glint` is the reusable core that satisfies §8** — the brief's own
  words are that inspect "reuses the same core glint but slower, travelling
  base→tip", i.e. the same component with slower `User.*` values. That core is
  built and driven by `User.Lifetime` + the material's U scroll.
* The four `EV_SWORD_INSPECT_*` names are **reserved and unimplemented**.
* **REQUESTED FROM THE SWORD / CHARACTER LINE:** an inspect move with its event
  list, so the events become real. Until then this row is `SPEC READY` and the
  Magic inspect requirements (§16: motion unchanged, motes base→tip during the
  blade/saya parallel beat, mist only on one side) cannot be verified.

This is the correct outcome under §0/§1 — marking it is the deliverable, not
guessing a duration.

| `EV_IAIDO_MOUTH_FIND` | `final_insert_start` | **7.900** | the tip finds the koiguchi; phase L becomes a pure translation | mist → ~0; the last 7 cm slow (`final_insert_slowdown 0.42`) |

| `EV_IAIDO_CUT` | `cut_start` (= `damage_time`) | **5.020** | the cut. `cut_angle_degrees = −30.0`, `cut_center = (0.5, 0.5)` | **purple void scar** — `NS_SW_Core_SpatialScar`, Magic instance |

**§22's "ONE rotation, not two spins" is satisfied by the Godot data, not by us:**
`spin_start 6.30 → spin_first_end 6.78 → spin_end 7.30`. `_apply_weapon_pose`
computes `turns = TAU * (first + second)` over those two eased spans, with
`spin_radius_first 0.038 → spin_radius_second 0.015` and `spin_lift 0.004`. So the
**total rotation is exactly one turn**, and the second arc SLERPs into the bore
orientation over its last third so the blade arrives already pointing down the
throat. UE5 must not add a rotation of its own.

**§22's "the mist is sucked back in, on the CLICK" is anchored to two real
instants:** `slow_sheathe_start 7.30` begins the reduction, `final_click 8.40` is
where it reaches zero. Godot also has a named window for exactly this —
`devour_start 8.40 → devour_end 9.15` — so "sucked back in" has a duration in the
source rather than being a taste call.

**Also relevant to a Magic Iaido:** `first_click 3.68` is a *separate, earlier*
click from `final_click 8.40`. The brief's `EV_IAIDO_CLICK` maps to the **final**
one at 8.40. The 3.68 click is a different beat and gets no purple point.

**The blade is never hidden.** `_apply_weapon_pose`'s closing comment: *"the blade
is never hidden. It goes inside a real scabbard and the scabbard's own walls
occlude it, which is the difference between a sheathe and a `visible = false`."*
So `EV_IAIDO_MOUTH_FIND` must not be accompanied by any VFX that fades the blade
out — the occlusion is real geometry.

## 11. User parameter manifest (Niagara side)

Brief §24 plus **four documented extensions**. Each extension exists because a
real module input refused the scalar form — recorded so nobody "cleans them up".

| Parameter | Type | Why |
|---|---|---|
| `User.PrimaryColor` | LinearColor | stroke body colour |
| `User.CoreColor` | LinearColor | hot core colour |
| `User.MistColor` | LinearColor | void / mist colour |
| `User.DarkColor` | LinearColor | void core colour |
| `User.Intensity` | float | drives `Color.Scale Alpha` |
| `User.Width` | float | ribbon width |
| `User.Length` | float | authored length |
| `User.Radius` | float | arc / burst / sprite radius |
| `User.ArcAngle` | float | arc sweep, degrees |
| `User.Lifetime` | float | particle lifetime |
| `User.Speed` | float | authored speed |
| `User.Distortion` | float | refraction strength |
| `User.MistAmount` | float | 0 = Normal, 1 = Magic |
| `User.SpawnRate` | float | primary emitter rate |
| `User.StartPosition` / `EndPosition` / `BladeBase` / `BladeTip` | Position | world anchors |
| `User.ArcStart` / `ArcEnd` | float | live arc draw-on (A4) |
| **`User.ScaleVector`** | **Vector3f** | **`ScaleMeshSize.Scale Factor` is Vector3f** — a float link there is a type lie |
| **`User.Velocity`** | **Vector3f** | **`SolveForcesAndVelocity.Velocity` is Vector3f** — same reason |
| **`User.MistCount`** | **int** | burst count for mist emitters; **0 in the Normal profile costs nothing** |
| **`User.MistRate`** | **float** | spawn rate for mist emitters; 0 in the Normal profile |

**Why `MistCount`/`MistRate` rather than a disabled emitter:** §23 and §4 require
one graph with different values. A disabled emitter needs the *component* to
enable it; a count of zero needs nothing. Same graph, different profile, and the
Normal sword pays zero for the Magic sword's emitters.

## 12. What the UE5 side must never do

1. Derive a time from `Lifetime`, a Delay module, or a curve. Ask for the event.
2. Give A2's sheet a different shape from A1's spine, or give A4 a 360° ring.
3. Let a Magic system differ from its Normal counterpart by anything other than
   **material instance + `User.*` values**. There is no `MagicSwordAttackA1()`.
4. Build A3's marks from one shared centre — the offsets in `move.traces` are
   what make three cuts countable.
5. Add a rotation during Magic Iaido. Godot already spends exactly one turn.
6. Invent an Inspect duration. Request the move instead.
