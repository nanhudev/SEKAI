# SEKAI 战斗动画需求 · Combat Animation Requirements

> 面向 ART 线与 Chat2Blender 产线的动画需求书。配套 `docs/COMBAT_DESIGN.md`。
> 本文件里的东西**不是建议**，是"没有它战斗就读不出来"的清单。

---

## 0. 为什么需要这份文档

当前第一人称武器由 `godot/scripts/player/temp_sword_visual.gd` 驱动：
它按 `SwordPoseSampler` 的权重曲线把剑摆到相机空间的姿态上（指数滞后弹簧 + tremor + 刀光）。
这已经能读，但**没有手**。

于是有两个必须解决的缺口：

1. **没有手/前臂** —— 第一人称剑没有握持者，剑像悬空的。
2. **没有骨骼动画** —— 所有动作都是程序化姿态插值，读得出来但"不像是人挥的"。

在正式手部与动画到位之前，程序化姿态是可接受的占位（README 已知不足里也写了）。
但**"只有 Transform tween、剑像飘"的实现不允许保留** —— 这一条是硬规则。

## 1. 硬性动画规则

每一刀必须具备五段，缺一段就不通过视觉评审：

| 段 | 作用 | 常见错误 |
| --- | --- | --- |
| **预备 Anticipation** | 反向蓄势，让玩家预判 | 直接进入斩击 = 无法读招 |
| **加速 Acceleration** | 权重曲线，不是匀速 | 线性插值 = 塑料感 |
| **接触 Contact** | 明确的一帧 | 没有接触帧 = 打击感消失 |
| **跟随 Follow-through** | 过头一点，再回来 | 停在接触点 = 动画像被截断 |
| **恢复 Recovery** | 回位，含可惩罚窗口 | 恢复太快 = 招式没有代价 |

**Weight Curve 走 `anticipation_power` / `strike_power` / `follow_power` / `recovery_power` 四个指数**，
不是四个关键帧的线性插值。数值已在 `moveset_library.gd` 里按招写死。

### 第一人称可读性

- 剑**可以**离开画面（比如落月的右上预备），但**必须重新进画面**，且进画面的时机要落在接触帧附近。
- **不允许**把剑甩到画面外然后靠音效糊过去。
- 大幅度横斩（落月、断水）必须在画面里留下**可追踪的轨迹**（`BladeTrail`，14 个刀尖采样点）。
- 刀光宽度是**流派参数**（`trail_width`），不是全局常量 —— 藏锋细、回风宽。

## 2. Sword Pose Anchors（剑姿态锚点）

所有流派的招式姿态都锚到这 5 个静止姿态上。姿态键写在**相机空间**
（x 右、y 上、−z 前），单位米 / 弧度。

| 锚点 | 用途 | 要求 |
| --- | --- | --- |
| **IdleAnchor** | 非战斗 / 战斗待机 | 剑尖略下、偏右；呼吸幅度极小；能被玩家当成"中性"参照 |
| **GuardAnchor** | 防御 Hold | 剑身立起挡在身前；需要**中线变体**（白蔷庭用）与**低架势变体**（藏锋用） |
| **SheathAnchor** | 纳刀静止 | 剑在鞘内、手在左腰；藏锋流的常驻姿态，必须读起来"没事干" |
| **HeavyWindupAnchor** | 重击蓄力上限 | 重量在前脚、剑过头；`断水` 用的静默版要把这一拍**拉长成 0.3s 静止** |
| **SprintAnchor** | 冲刺中 | 剑略后收、身体前倾；不能挡住视野中心 |

### 变体清单（同锚点不同性格）

| 变体 | 归属 | 差异 |
| --- | --- | --- |
| GuardAnchor · 中线 | 白蔷庭（设计态） | 剑尖指向对手中线，站姿最窄 |
| GuardAnchor · 低架势 | 藏锋流 | 剑放低位、刀尖朝下偏外，读起来"还没拔" |
| SheathAnchor · 左腰 | 藏锋流 | 一文字的起点，必须和 SheathAnchor 无跳变 |

**关键约束**：姿态锚点之间**不允许瞬移**。藏锋流的纳刀/拔刀是 lerp（`sheath_amount`），
ART 交付的动画如果首尾姿态与锚点不一致，驱动器会在进入动画的那一帧弹一下。

## 3. Ultimate 动画钩子（全新资产，禁止复用聚合斩）

无明一刻需要**四个独立动画资产**。它们与聚合斩（`iaido`）**不得共用任何文件**。

| 钩子 | 时长 | 内容 |
| --- | --- | --- |
| **UltimateReady** | ~1.55s | 从 IdleAnchor 到就位。呼吸停掉、身体沉下来。不需要特效，特效是引擎侧的 |
| **UltimateDraw** | **≤0.15s** | **一次几乎看不见的拔刀**。这是全局最短的关键动作，长度就是"看不见"本身 |
| **UltimateHold** | ~1.0s | 拔刀后到纳刀前的静止。**不能有任何多余动作** —— 这一秒是"什么都没发生" |
| **UltimateSheathe** | ~0.75s | 纳刀，收尾要**慢**，慢到玩家开始怀疑刚才是不是没打中 |

- 四个钩子之间**必须有姿态连续性**，因为它们是同一段演出的四拍。
- `UltimateDraw` 与 `UltimateSheathe` 的首尾帧要能对接 `UltimateHold`。
- 演出总长 4.85s（引擎时间轴），动画资产按上表长度交付即可，中间空隙由引擎保持姿态。

> 再次强调：聚合斩 = "这一招本身即演出"；无明一刻 = "一次拔刀产生多个结果"。
> 两者可以共享**风格**（蓝 / 玻璃 / 世界切割），但不能共享**资产**。

## 4. 招式级动画需求表

### 通用层

| 招式 | 视觉重点 |
| --- | --- |
| `uni_l1` 右上→左下 | 起手要"轻"，让玩家知道这是可以连的 |
| `uni_l2` 左→右 | 反向横斩，视觉上承接 L1 的落点 |
| `uni_l3` 收鞘一拍 + 突刺 | **换节奏的那一拍**，突刺必须比前两下明显更长更直 |
| `uni_heavy` 劈砍 | 垂直/斜向，重量前压，接触后剑要"停住"一下 |
| `uni_sprint_light` | 冲刺姿态下起手，前冲但不做远距离吸附 |
| `uni_retreat_light` | 边退边换线，身体后倾 |
| `uni_riposte` 快速短突刺 | **短、直、快**。不允许长演出 |

### 藏锋流

| 招式 | 视觉重点 |
| --- | --- |
| `he_ichimonji` 一文字 | 左腰**瞬间拔刀**，0.055s 起手 —— 视觉上要像"刀已经在外面了" |
| `he_kaeshi` 返刃 | 反向斜斩。命中变快 / 空挥变慢，所以**两个版本都要有**（或至少让收尾可被截断） |
| `he_rakugatsu` 落月 | **持刀一拍**的停顿，然后右上→左下重斩 |
| `he_dansui` 断水 | 0.3s **绝对静止**，然后极快横斩。静止占整个动画的 40%，这是刻意的 |
| `he_sokyu` 纳息 | 强化态的过渡动作，**不做光环**，只有姿态变化 |
| `he_tsubame_1/2` 燕返 | 上斜 → 反向下斜组成 X。**第二段只在命中后出现** |
| `he_danzhang` 断章 | 精准一击，动作幅度小，力道集中在一点 |

### 回风式

| 招式 | 视觉重点 |
| --- | --- |
| `fw_l1` 横 | 环绕横斩，身体已开始转动 |
| `fw_l2` 返 | 斜向回返，承接上一段的转动惯性 |
| `fw_l3` 进 | **短步突刺**，脚要跟着进 |
| `fw_l4` 环 | 环形收尾，转完身体回到正面 |
| `fw_liuyun` 流云 | 位移动作，读起来是"飘过去"而不是"冲过去" |
| `fw_zheliu` 折柳 | **让攻击擦过去**：身体滑开一条线，不是格挡也不是闪避。身体先动、剑后到 |
| `fw_jinghong` 惊鸿 | 衔接用的转身抬手，幅度小、可被打断，作用是"把动作串起来" |
| `fw_changfeng_1/2/3` 长风 | 三段**定向**斩。1 右横 / 2 左横返 / 3 上段落。每段都必须有**侧向**的姿态可镜像版本（`player_aimed` 会镜像 x/z 旋转），因为方向由玩家输入决定 |

**长风的动画约束（硬）**：三段之间**不得锁死**。每段末尾都要能接回通用 Idle / 闪避 / 格挡。
玩家在开这套剑，不是看这套剑 —— 任何"必须看完"的设计都违背这个流派的承诺。

### 白蔷庭（Prototype 已实现，动画需求升级为 P1）

| 招式 | 视觉重点 |
| --- | --- |
| `wr_l1` 横 | **短**横切。不是横扫，是关于中线的短促划开 |
| `wr_l2` 刺 | 剑尖走一条**直线**，身体几乎不动。读作"点"，不是"挥" |
| `wr_l3` 反 | 反手小斩，收得极快。**没有收招定型**，因为它要立刻回接第一式 |
| `wr_chuanting` 穿庭 | 极短起手 + **长伸距**。重点是剑尖伸出去的距离，不是身体跨出去的距离 |
| `wr_jiazhang` 假章 | 起手与 `wr_chuanting` **必须前 80% 完全一致**，否则骗不到人。差别只在"收不收" |
| `wr_baqiangci` 白蔷刺 | 起手最快的一招，剑尖几乎瞬间到位。极窄，容错低 |
| `wr_bind_thrust` 合围刺 | 从缠剑里沿对方剑身**滑入**的突刺 —— 起点是两剑相抵，不是空手起手 |
| `wr_bind_disengage` 脱手斩 | **一边退一边切**。脚向后、剑向前，身体重心要读得出来 |

**白蔷庭的动画约束（硬）**：
1. 剑尖必须**一直在中线附近**。这是这个流派唯一的视觉签名。
2. `wr_jiazhang` 与 `wr_chuanting` 的起手帧必须能互换使用（同一套 wind 姿态），
   否则 `feint` 机制在视觉上就不成立。
3. `BindHold`（两剑互锁的那一拍）是**新姿态**，不是 Guard 变体 —— 剑身角度完全不同。

## 5. 缚星链姿态锚点与动画需求

**先说清楚一件事，否则这一节的每一条都会被做错。**

链头**不是**骨骼动画：它由 `ChainDirector` 的极坐标状态机驱动（方位角 / 半径 / 高度），
链接由 `ChainVisual` 画成一条解析曲线。这是硬性设计（`COMBAT_DESIGN.md` §19），
所以 **ART 不要为链做"招式动画"**。ART 要做的是三件事：

1. **武器资产拆分**（§5.3）
2. **手 / 前臂的锚点姿态**——链是「手的延伸」，手感的一半在手臂上
3. **命中与绷紧的反应**——手指头有重量，手臂必须同意

### 5.1 与剑的根本区别：手跟着链头，不是链头跟着手

剑的动画是**手主导**：姿态锚点决定剑在哪。
链是**链头主导**：数据决定链头在哪，手必须**跟着**，否则第一人称里会出现
"手在挥、链头在别处"的断裂——这是最容易被忽略、也最毁第一人称链感的一个错误。

因此：手部姿态请按**相对相机空间**做，并且**允许被程序化延迟/滞后修改**
（`TempSwordVisual` 已经在用指数滞后弹簧 + tremor，同样的机制会接到链手上）。

### 5.2 锚点清单（链专用）

| 锚点 | 什么时候 | 要点 |
| --- | --- | --- |
| **IdleHold** | HELD 待机 | 链柄垂在身体侧后下方，**不是举着**。链头在 0.62m 高度缓慢摇摆 |
| **ThrowAnchor** | 缠锁（抛出） | 前臂向前释放，**手腕必须能上抬到约 35°**：抛出方向跟着准心走，抬头 28° 时链头要往头上飞 |
| **OrbitAnchor** | 蓄势回旋（按住重击） | 手臂画圈。**这一条不能做成一个 keyframe loop**：回旋持续时间由玩家决定（0.14–1.30s），需要一个可循环、可从任意相位进出的姿势 |
| **BindAnchor** | 缚（绷紧、挂着东西） | **肘部锁死、手腕翻转**。绷紧的视觉一半在链（直线的微颤），一半在手臂（在用力） |
| **ReelAnchor** | 回收中 | 肘部向后收。**注意：回收会先过冲再回来**，所以手臂的头几帧要**跟着链头往外**，不许立刻往回拉 |
| **BindBreakAnchor** | 缚松脱 / 拉近斩 / 地砸 | 链突然松开的瞬间，手臂要有一次**释放**（不是收回），然后才回到 IdleHold |

### 5.3 ART REQUEST：链的四个部件（§47）

**不要**把链烘成一根固定长度的模型。必须分离：

| 部件 | 说明 |
| --- | --- |
| `Chain Handle` | 左手握柄 + 尾环。第一人称永远可见，**必须与 C2B-02 的左手（如果做）严格对齐** |
| `Chain Link` | **单个**链节。长度由 `ChainMoveset.chain_length` 决定，链接数量由代码算 |
| `Chain Terminal Head` | 刃锤：有重量感，短刃 + 配重球。**朝向必须从任意角度看都清楚**（链头会离开画面，玩家必须能找回它） |
| `Chain Connector` | 链节之间 / 链节与柄、头的连接件 |

**三形态共用同一套武器语言**：游链 / 律链不做新的固定模型，律链的虚拟链由 VFX 表现。

### 5.4 本能反应（本轮新增的手感规则，动画必须同意）

这一轮给实链加了"链头有质量"的机制，其中三条**直接改变手臂该做什么**：

| 机制 | 数据 | 手臂必须 |
| --- | --- | --- |
| **落点代价** | 命中按目标重量扣势，弧线被撞偏 2–10° | **命中瞬间有一次反冲**。链头被撞偏了，手臂却纹丝不动，就会读成"穿模" |
| **回收过冲** | 回收先外漂 0.13m、多转 10.8° 再回家 | 头几帧跟着往外，**不要**立刻收肘 |
| **绷紧** | 线在满绷时高频微颤 | 手臂是**静态用力**（锁肘），不要跟着抖：抖的是链，不是人 |
| **命中顿住** | hitstop 0.03–0.07s（随链头速度与目标重量） | 顿的那一下，手也停 —— 这是 hitstop 的本质 |

### 5.5 现状

链**完全没有动画与手部**：`ChainHandleVisual` 是程序化的圆柱 + 圆环，链节是 MultiMesh 方盒，
链头是方盒 + 球。**这是刻意的占位**（`CHAIN VISUAL REQUEST` 尚未排产），
但它已经是第一人称可读的——`tests/chain_integration.gd` 守着"链画在它该在的地方"。

## 6. # ART REQUEST

### C2B-02 · First Person Hand / Forearm（P0，已 SPEC READY）

| 项 | 要求 |
| --- | --- |
| 内容 | 右手 + 前臂（第一人称），可动持剑 |
| 风格 | Anime Stylized Fantasy + Stylized Next-Gen + PBR。**禁止** generic low-poly / mobile toy style |
| 面数 | 性能优先。60 FPS > 面数炫技 |
| 握持 | 必须与 C2B-01（First Person Sword，832 tris，已在 `godot/models/weapons/`）握柄**严格对齐** |
| 管线 | ChatGPT Web (GPT-5.6 Sol) 写 bpy → 可见 Blender 执行 → 视觉检查 → GLB → Godot |
| 分块 | 按 `# C2B:CHUNK <name>` … `# C2B:END`，每块独立可运行 |
| 验收 | **Godot 第一人称是唯一验收场**。Blender 里好看不算 |

**给 CHATGPT 的补充指令**：手部不要做高细节指甲/皱纹 —— 第一人称只会看到手背与指节。
重点放在**握柄贴合**与**手腕可旋转范围**，因为所有挥砍都靠手腕。

### 魔法相关的动画需求（本轮新增）

| 项 | 要求 |
| --- | --- |
| Quick Magic | **主手剑不得消失**。副手在 `startup` 内出手，`recovery` 内收回。火种 / 风压 / 冰爆共用一套骨架 |
| Heavy Magic | 允许完整 Cast Pose（双手或单手举出）。目前只有焚环一个法术用得上 |

**排产原则**：锚点先于招式。锚点不对，所有招式的首尾帧都要返工。
