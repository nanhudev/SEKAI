# SEKAI 战斗设计 · 单手剑语言与流派

> 本文是战斗系统的权威设计文档。代码里的数值以 `godot/scripts/combat/moveset_library.gd` 为准，
> 本文解释**为什么是这些数值**，以及哪些已经实现、哪些只是设计。
>
> 分支 `godot-combat-mvp` · Godot 4.4.1 · Compatibility 渲染器

---

## 0. 一句话设计立场

**先把"普普通通用剑砍人"做到好玩，再谈流派。**
流派不是新的战斗系统，而是**同一套剑语言上的数据改写**：节奏、方向、取消窗口、位移、架势、反击、技能。
永远不允许为某个流派写第二个 `CombatController`。

判断这套设计成不成立只认两条：

1. **阶段一**：只用通用剑（无技能、无流派）对 Technical Dummy 打，必须已经有趣。
2. **阶段二**：切到藏锋流后，玩家**不看 UI** 就能感觉到"这是另一把剑"。
   差异必须来自动作、节奏、窗口、声音、反馈 —— **不是伤害数字**。
   如果玩家的最优解仍然是"无脑连点左键"，藏锋流设计即**失败**。

## 1. 架构：数据改写，不是继承

```
CombatController          ← 只认"剑语言"，从不 if style_id == ...
    └── SwordMoveset      ← 一个流派 = 一份数据（节奏/窗口/姿态/声音/位移）
            ├── SwordMove        ×N   单招的时间轴与姿态曲线
            ├── SwordGuardProfile      防御与完美格挡的行为差异
            └── SwordSkill       ×N   技能（数据指向 move_id）
```

| 文件 | 职责 |
| --- | --- |
| `sword_move.gd` | 一招：`startup → wind → strike → contact → follow → recovery` |
| `sword_guard_profile.gd` | Hold / Perfect Guard / Riposte 三个子行为 |
| `sword_skill.gd` | `ATTACK` / `ENHANCE` / `INTERRUPT` / `MOBILITY` |
| `sword_moveset.gd` | 流派装配 + 姿态刚度/颤抖/刀光宽度 + 纳刀节奏 |
| `sword_pose_sampler.gd` | 把时间轴采样成相机空间姿态（权重曲线） |
| `moveset_library.gd` | 全部流派在代码里构建；**唯一新增流派的地方** |
| `combat_controller.gd` | 状态机、输入缓冲、取消规则、命中结算。**不认识任何流派名** |

### 姿态求解

姿态键位写在**相机空间**（x 右、y 上、−z 前），由武器驱动器用指数滞后的弹簧逼近：

```gdscript
tau    = 2.2 / stiffness
follow = 1.0 - exp(-delta / tau)
```

再叠加 `tremor`（颤抖）、`intensity`（招式强度）、`look_lag`（视角延迟）、`root_inverse`（根空间补偿）。
**禁止**只留一条 Transform tween —— 那会让剑读起来像"飘"。
每一刀必须有预备蓄势 → 加速 → 接触 → 跟随过头 → 回位，且自带 Weight Curve。

### 时间轴要不要缩放，缩哪一段

招式的"尾巴"（follow-through + recovery）才是**流派**要改写的东西。
所以 `recovery_scale` 缩放的是整个尾段，而不是只缩 `recovery`；
否则一个快流派身后会拖一条属于慢流派的跟随动作。

## 2. 通用剑语言（Universal）

所有流派共享的生命线。通用层**没有大招**（`ultimate_id = &""`）—— 大招属于流派，不属于语言。

### 轻攻击三段

| 招式 | ID | startup | strike | follow | recovery | 总计 | 方向 | 备注 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| Light 1 | `uni_l1` | 0.085 | 0.085 | 0.075 | 0.175 | **0.420** | 右上 → 左下 | 起手 |
| Light 2 | `uni_l2` | 0.095 | 0.090 | 0.075 | 0.180 | **0.440** | 左 → 右 | 反向横斩 |
| Light 3 | `uni_l3` | 0.125 | 0.085 | 0.090 | 0.200 | **0.500** | 收鞘一拍 + 快速突刺 | **必须换节奏** |

- 设计窗口 L1 0.32–0.42s / L2 0.34–0.44s / L3 0.42–0.55s —— 全部落在区间内。
- **L3 是突刺**（`contact_rot.x < -1.0`），startup 最长、poise 最高。
  玩家的肌肉记忆是"两下快、第三下顿一拍再捅" —— 这就是"换节奏"的可读形式。
- 输入缓冲 100–180ms：取消可以续链，`chain_active` 让"取消 → 再按"承接同一套连段，
  而不是重新起手。

### 重攻击：Tap / Hold 分家

| 招式 | ID | startup | strike | follow | recovery |
| --- | --- | --- | --- | --- | --- |
| Heavy · Cleave | `uni_heavy` | 0.185 | 0.105 | 0.100 | 0.300 |

- `heavy_charge_time = 0.8s`（蓄力上限），`heavy_tap_grace = 0.18s`（低于此算 Tap）。
- **Tap 与 Hold 的差别是"姿势伤害 + 受击反馈"，不是伤害 ×2。**
  Hold 抬高 `move_poise_scale`，同步抬高命中框的 poise 值；伤害只做温和加成
  （`charged_damage_bonus`），`charged_poise_bonus` 才是主菜。
- 重量前压、垂直/斜向劈砍，命中时把敌人推开而不是"打得更疼"。

### 移动攻击

| 招式 | ID | 说明 |
| --- | --- | --- |
| Sprint Cut | `uni_sprint_light` | 冲刺中轻击；`lunge` 给前冲，但**不要远距离自动吸附** |
| Retreat Cut | `uni_retreat_light` | 后撤中轻击，边退边换线 |

### Riposte

| 招式 | ID | startup | strike | follow | recovery |
| --- | --- | --- | --- | --- | --- |
| Riposte | `uni_riposte` | **0.055** | 0.070 | 0.060 | 0.200 |

**默认反击是"快速短突刺"，不是长演出。** 完美格挡已经给了 50–80ms hitstop 的仪式感，
反击本身要立刻、干脆、不打断战斗流。

## 3. 防御 / 完美格挡 / 反击闭环

### 防御不是无敌

| 行为 | 结果 |
| --- | --- |
| 普通 Hold | 减免伤害（`damage_multiplier`），但照扣耐力；重击双倍扣（`heavy_stamina_multiplier`） |
| 耐力归零 | 破防：耐力损失 + 相机冲击（trauma）+ 武器后坐（`guard_recoil`） |
| 完美格挡 | 见下 |

### 完美格挡（窗口 0.12s，可调 0.08–0.16）

一次成功的完美格挡必须**在五个通道同时给反馈**，任何一个缺失玩家就读不出来：

1. **武器后坐** —— 武器被弹开（`guard_recoil`）
2. **相机冲击 + hitstop** —— 50–80ms 时间停顿
3. **敌人攻击被中断** —— 敌人进 STAGGER，`attack_phase_changed` 触发电报环熄灭
4. **小火花 VFX** —— 金属对撞的那一点白
5. **锐利的金属瞬态音** —— 见 `COMBAT_SFX_BRIEF.md` Priority A

随后**开启 Riposte 窗口 0.75s**（设计区间 0.5–0.9s）。
窗口内按轻击 = 该流派的反击招（`riposte_id`），不是固定动作。

**一个诚实的边界**：按住防御超过窗口**不算**完美格挡 —— 但仍然扣耐力、有后坐、有减免，状态留在 BLOCK。
"按住不放就能完美格挡"是这类系统最常见的退化，测试里专门锁住了这条。

### 截锋（藏锋流的完美格挡形态）与"刀锋微光"

藏锋流的完美格挡不是"挡"，是**用极短的拔刀动作切断攻击线**，然后立刻回低架势。
奖励不是跳一个增益图标，而是**刀锋上出现一道微光（`edge_glint`）**：

- 下一发**一文字** startup ×0.74（通用层是 ×0.84）
- 第一击 poise ×1.4+

表现层只有刀刃亮一下。**不用大 UI 增益条** —— 那是把设计意图喊出来给玩家听。

## 4. 流派：藏锋流 · Hidden Edge

> 断奏型。观察 → 纳刀 → 等待 → 爆发 → 短链 → 再纳刀。

**代价必须真实**：持续输出弱、空挥恢复长、爆发/反击/姿势强。
玩家的正确打法是"等一下再动手"，而不是"多按几下"。

### 核心机制：纳刀与拔刀

| 参数 | 值 | 含义 |
| --- | --- | --- |
| `sheath_enabled` | true | 闲置自动纳刀 |
| `sheath_delay` / `sheath_time` | 见数据 | 站定一段时间后收刀，收刀有过程 |
| `sheathed_startup_scale` | **0.72** | 带刀出鞘的拔刀斩起手更快 |
| `sheathed_poise_scale` | >1 | 拔刀第一击姿势伤害更高 |
| 连段 | 会**打断**纳刀 | 想保持拔刀红利就不能乱按 —— 这就是节奏约束 |

### 轻链

| 招式 | ID | 备注 |
| --- | --- | --- |
| **一文字** | `he_ichimonji` | startup **0.055**（全游戏最快起手）。左腰瞬间拔刀 |
| **返刃** | `he_kaeshi` | 反向斜斩。`hit_recovery_scale 0.66` / `miss_recovery_scale 1.50` / `on_hit_next_startup_scale 0.72` |
| **落月** | `he_rakugatsu` | 持刀一拍，右上 → 左下重斩 |

返刃是藏锋流设计的缩影：**命中就更快，空挥就更慢。**
命中 vs 空挥的 recovery 差 2.3 倍 —— 这一条就是"看准了再打"的全部。

### 重攻击：断水

| 招式 | ID | startup | anticipation_power |
| --- | --- | --- | --- |
| **断水** | `he_dansui` | **0.300** | **6.0** |

绝对静止 0.3 秒，然后极快横斩。`anticipation_power 6.0` 是通用层的 3.5 倍 ——
预备动作被刻意拉长成"你确定要挨这一下吗"的静默。
对 Frozen 目标有额外 Shatter 交互（`frozen_bonus`）。

### 技能

| 技能 | ID | Kind | 效果 |
| --- | --- | --- | --- |
| **纳息** | `he_sokyu` | ENHANCE | 6–10s 强化态：改起手 / 窗口 / 第一击姿势 / 纳刀恢复。视觉**克制**，不做光环 |
| **燕返** | `he_tsubame` | ATTACK | 命中后才有反向斜斩组成 X 斩；**空挥没有免费第二下** |
| **断章** | `he_danzhang` | INTERRUPT | 精准一击，强力打断敌人施法 / 起手 / 蓄力 |

燕返的两段是 `he_tsubame_1` → `followup_id = he_tsubame_2`（`requires_hit = true`）。
"空挥不给第二段"由 `requires_hit` + `followup_window` 数据保证，不是脚本特判。

### 姿态性格

藏锋流的 `pose_stiffness` 更高 —— 刀更"硬"，回位更干脆；
配合高 `tremor`，读起来是"绷着的"而不是"晃着的"。回风式相反。

## 5. 流派：回风式 · Flowing Wind

> 流 / 转 / 接 / 移。连上了才顺，断了就散。

### 四段链

| 招式 | ID | 方向 |
| --- | --- | --- |
| 回风 · 横 | `fw_l1` | 横斩 |
| 回风 · 返 | `fw_l2` | 斜向回返 |
| 回风 · 进 | `fw_l3` | 短步突刺 |
| 回风 · 环 | `fw_l4` | 环形收尾 |

### 流的核心：命中才缩短

| 参数 | 通用/藏锋 | 回风式 |
| --- | --- | --- |
| `flow_on_hit_recovery` | 1.0（不缩） | **0.60** |
| `flow_min_recovery` | — | 0.085（保底） |
| `combo_window` | 0.30 | **0.52** |
| `steer`（转向权） | 基准 | **> 2× 藏锋** |

- **连上 → 下一段 recovery 缩短**；**空挥 → 节奏断裂**（不缩）。
  测试锁的是相对比较（`connected_end < whiff_total * 0.85`），避免写死绝对秒数。
- 移动转向显著强于藏锋：回风式是**边打边绕**的剑，藏锋流是**站定再拔**的剑。
  这一条就是两个流派"不看 UI 也能分辨"的物理来源。
- 防御是 Deflect 型：减免更低，但完美格挡后能立刻侧移重新站位。

### 已实现技能

| 技能 | ID | Kind |
| --- | --- | --- |
| **流云** | `fw_liuyun` | MOBILITY |

### 已实现（本轮补齐）

- **长风**（SIGNATURE，不是大招）：玩家自己连开三段定向斩。每段用 `followup_from_start`
  在**起手**就打开 follow-up 窗口，方向由移动输入决定（`player_aimed` + pose/hitbox 镜像）——
  所以是**玩家在开剑，不是演出在开剑**。随时可以离开，不会锁住动画。
- **流云**（MOBILITY）：短位移 + 斜切。是**进攻位移**，不是闪避升级。
- **折柳**（SLIP）：让攻击落空。与完美格挡相反 —— 不是对抗，是不接。
- **惊鸿**（ENHANCE）：短期强化衔接（`enhance_transition_bonus` / `enhance_steer_bonus`），
  是**势的放大器**，不加伤害。

`SwordSkill.Kind` 上新增了 `SLIP`：一个"把攻击让过去"的窗口，
和"把攻击接下来"的完美格挡形成语义对立。

### 仍为设计态（未实现）

- **长风万里**（大招）：延展风场 + 长距离位移斩，**不与无明一刻共用任何资产**。

回风式当前 `ultimate_id = &""` —— **空着是故意的**，
宁可没有大招，也不塞一个凑数的。

## 6. 流派：白蔷庭剑术 · White Rose School（Prototype 已实现）

> 距离 / 精准 / 突刺 / 招架 / 缠剑。不模拟史实剑术，只要"贵族决斗"的干净感。

§53 的自问：**玩家会不会开始主动控制距离？** 如果答案是否，这流派就只是换皮。

### 剑的性格

- 站姿最窄最直，剑尖控在对手中线。
- 攻击以**突刺**与**小幅度精准斩**为主，几乎没有大幅度横斩。
- 三段链 **没有收尾大招**：第三式 反 不是 finisher，命中后**回接到第一式**，把威胁续下去。
  这是机制不是形容 —— follow-up 只在**命中**时打开，所以打空就是真的结束。
- `tremor 0.0022` / `trail_width 0.018`：精准读作"噪音更少"，不是"特效更多"。
- `dodge_cancel_from = 0.46`（四流派里最晚）：站错位置的代价最大，所以也不能同时很灵活。

### 核心机制：Measure（距离）

**没有额外资源条。** 控制器每帧从玩家正前方一个 55° 锥形里找最近的目标
（`combat_target` 分组 —— 敌人不需要被"认识"，加进组就会被量到），按距离分三档：

| 档位 | 距离 | 后果 |
| --- | --- | --- |
| Too Close | < 1.50 m | startup ×1.25、posture ×0.70 |
| Ideal Measure | 1.50–3.20 m | startup ×0.80、posture ×1.55、**突刺类额外 +0.30 m 伸距** |
| Too Far | > 3.20 m | startup ×1.20、posture ×0.85 |

**Measure 不给伤害。** 只给起手、伸距与姿态。否则流派就从"控制距离"变成"站在对的位置收数值"。

采样时机是**承诺那一刻**（`_begin_move`），不是每帧 —— 挥剑途中往前走不能补领奖励。
正前方没有人时档位是空（`&""`），不是"太远"：空场不算一场架。

### 重攻击：穿庭

起手 0.135s（对重击而言极短），伸距 2.20 m，几乎不做 `lunge_lead` ——
重点是**刺得远**，不是**跨得远**。理想距离下姿态伤害过线（≥50，等于一次 posture break）；
贴脸则只是一记普通重击。**这一招就是整个流派。**

### 完美格挡 = 缠剑（Bind）

完美格挡后**不把人打飞、自己也不侧移**（`parry_steer = 0`）。剑被锁住 0.30s，玩家三选一：

| 输入 | 出口 | 含义 |
| --- | --- | --- |
| 轻击 | `wr_bind_thrust` 合围刺 | 留在距离里回答 |
| 重击 | `wr_bind_disengage` 脱手斩（`lunge = −0.95`） | 一边退一边切 |
| 闪避 | Side step | 直接换线 |

窗口 0.2–0.4s：长到够选，短到"不选"本身也是选择。
刻意比其它流派的 riposte 窗口（0.5–0.9s）短 —— **奖励是那个选择，不是那段时间**。
`moveset_integration` 里给这一条留了显式例外。

### 技能（Phase 1 只有两个）

- **假章**：像穿庭一样的起手，但在剑真正出去之前就能收回。靠 `feint_cancel_from = 0.55` ——
  整个招式词汇表里**唯一**一个在 startup 期间开出口的字段（`feint` 就值一个字段）。
  骗格挡、骗反击用。
- **白蔷刺**：极窄极长的精准刺（0.55 × 2.6 m）。难瞄、容易空，理想距离下姿态伤害过线。

### 暂不实现

`signature_id = &""`、`ultimate_id = &""`。Measure 循环没被证明之前先做大招，
正是这一轮要避免的错。

## 7. 元素三系 · Fire / Frost / Wind（行为，不是颜色）

> 唯一的验收标准：**只看行为，不看数值，能不能分辨这三系。**
> 火不是"红伤害"，冰不是"绿伤害"，风不是"绿色投射物"。

### 规则写在哪

| 文件 | 职责 |
| --- | --- |
| `element_definition.gd` | `ElementDefinition`：一系元素的**全部规则** |
| `element_state.gd` | `ElementState`：某个角色身上"有多少"，含衰减 / 延迟 / DOT / 跨元素加速 |
| `element_field.gd` | `ElementField`：地面上活着的一片元素（法阵、火场） |
| `element_library.gd` | 三系的**唯一**书写处，且**实例是共享的**（单例缓存） |

`ElementState` 不认识"冰"是什么，只回答"变了没有"。敌人里**不存在** `if element == frost`。

> 把 `ElementLibrary.frost().applies_per_hit` 在运行时改掉，冰的行为就跟着变 ——
> 这是"规则即数据"最强的证明，也是 `element_magic_integration` 断言的第一件事。
> 共享实例是这条断言的前提：如果每次调用都新建一份，"唯一书写处"就是假的。

### 三系各自的性格

| | 火 FIRE | 冰 FROST | 风 WIND |
| --- | --- | --- | --- |
| 问玩家的问题 | 我想在哪打？ | 我怎么造下一次 Shatter？ | 我想让谁在哪？ |
| 结构 | 开 / 关（无阶梯） | 四阶阶梯 normal→chilled→frosted→frozen | 开 / 关（无阶梯、无 DOT） |
| 主要效果 | 持续伤害 + 恐慌 + 蔓延 | 逐阶改变行为，顶阶短暂且**脆** | 按重量推动、打断、撞墙 |
| 与剑 | 剑穿过火环 → 短暂 **火刃** | 剑穿过寒流 → **霜刃**（叠冰更快） | 不附魔，改位置 |
| 反制关系 | **烧退冰**（`hastens_decay_of = [FROST]`，×2.5） | 被火克 | 只对轻物有效 |

**Frozen 不是"敌人被关掉 10 秒"**：`final_stage_duration = 4.0`，且 `enables_brittle`。
顶阶的价值是**它创造的开口**，不是它取消了一个敌人。

**Burning 不是"每秒掉血"**：它至少同时做四件事 —— 持续伤害、弱敌恐慌（`panic_health_fraction`）、
加速冰的消退、被风吹走（`spread_by_wind`）。

**Wind 不是投射物**：效果由重量决定（轻 1.6 / 中 1.0 / 重 0.25），
并且**真的会推物理物体、真的会撞墙**（见 §16 环境）。

补充：风的推力方向是**水平**的（`WindProps.blow` 与敌人 `_push_from` 都压平 y）。
否则低头瞄准会把阵风打进地板，俯仰角就悄悄变成了风的强度乘数。

## 8. 剑 × 魔法：第一批五种交互

> 最有价值的部分。不是"剑伤害 + 魔法伤害"，而是**魔法改变状态，剑去兑现状态**。

| # | 交互 | 机制所在 | 玩家的感觉 |
| --- | --- | --- | --- |
| 1 | **Frozen + 重击 → Shatter**（参考组） | `technical_dummy._on_hit` 第一分支 | 我造了状态，我兑现它 |
| 2 | **风吹 → 撞墙 → 姿态**（Environment Collision） | `_push_from` + `WindProps` | 我改的是**位置**，墙替我打 |
| 3 | **火 → 风 → 蔓延 / 加强** | `ElementField.spread()` + `wind_spread()` | 我不是在加伤害，我在扩大战场 |
| 4 | **Frosted + 藏锋 断水 → Brittle Break** | `_on_hit` 第二分支 | 冰和藏锋天然合得来 |
| 5 | **风步 → 回风轻链 → 高势** | `speed_multiplier()` + Flow | 风让回风更快进入"势" |

第 1 条是**标尺**：其它四条都拿它比较"是否同样改变决定"。

- **COMBO 3 不是"伤害 ×1.5"**：风把火场的半径与持续时间扩开（`spread(multiplier := 1.45)`），
  是把"哪里能打"变大。
- **COMBO 4 刻意比 COMBO 1 早一档**：Frosted（不是 Frozen）+ 重击 = Brittle Break。
  让"重击对冰"有两个不同的理由，而不是同一件事换个名字。
- **COMBO 2 是唯一需要环境的**：没有墙，风就只是一个击退数字。

## 9. 战斗矩阵：3 × 3 的倾向，不是 12 个条目

流派回答"怎么打"，魔法回答"怎么改局面"。**两边正交。**

### 行：流派 → 核心决定

| 流派 | 核心决定 | 玩家的自问 |
| --- | --- | --- |
| 通用 Universal | 基本功 | 我会不会用剑？ |
| 藏锋 Hidden Edge | **时机** | 我等不等那一刻？ |
| 回风 Flowing Wind | **移动** | 我有没有为了不断势而主动跑起来？ |
| 白蔷庭 White Rose | **距离** | 我有没有主动控制距离？ |

### 列：魔法 → 核心决定

| 魔法 | 核心决定 | 玩家的自问 |
| --- | --- | --- |
| 火 Fire | **区域 / 蔓延** | 我想让这场架在哪打？ |
| 冰 Frost | **铺垫 / 控制** | 我在造下一次 Shatter 吗？ |
| 风 Wind | **位置 / 力量** | 我在改谁的位置和动量？ |

### 关键约束：**不要**把流派绑死到元素

系统里**不存在** `藏锋 = 冰`、`回风 = 风`、`白蔷 = 火`。
有些组合确实更顺手（藏锋 × 冰、回风 × 风），但玩家仍然可以做藏锋 × 火、藏锋 × 风、
回风 × 冰、白蔷 × 风，而且**结果不同**。
`combat_lab_integration` 用 4 流派 × 3 元素**全排列**断言了这一点。

乘法生长的意思是：加一个流派 = 多三行结果，而不是多一个条目。

## 10. 第四剑术：坠星式（**仅设计，不实现**）

> 重量 / 承诺 / 破甲 / 对拼 / 力。意象：陨星、巨石、雷霆。

存在的理由：确保未来的系统里真的有**重**，而且与藏锋的"重"不同。

| | 藏锋 | 坠星式 |
| --- | --- | --- |
| 重的来源 | 蓄势后的**爆发** | 剑本身**就重** |
| 代价 | 等待时间 | 起手长、几乎无法取消、位移大 |
| 赢的方式 | 等一个破绽 | 用承诺换交换（trade） |

草案要点：

- **没有轻链**，只有三记独立的"落"。每记起手 ≥ 0.35s，`cancel_open` 极晚，`dodge_cancel_from ≥ 0.8`。
- 命中时不是"伤害高"，而是**打断 + 破甲 + 强制硬直**：对重敌有效，对快敌几乎无解。
- 与元素：**风完全推不动他**（`WEIGHT_HEAVY` 是下限），火 / 冰的状态堆积更慢。
- 形态语言：不是"挥"，是"落"。姿态曲线 `strike_power` 反而**低**（没有加速段），
  `follow_power` 高（砸下去的余量）。
- 验收问题：**"玩家会不会开始在意自己有没有站在对的位置上、以及这一下能不能收回来？"**

不实现的原因：它需要完全不同的姿态语言与重量反馈（hitstop、镜头、脚步、破坏材质）。
在"距离 / 移动 / 时机"三条线还没测完之前上马，只会得到第四种换皮。

## 11. 聚合斩：保留为 SIGNATURE（不是大招）

聚合斩继续保留全部既有演出：世界冻结 → 反向波 → 左腰收刀 → FOV 扩张 → 瞬间拔刀 →
世界切裂 → 蓝虚空 → 玻璃碎裂 → 双段转体 → 缓慢纳刀。

| 项 | 值 |
| --- | --- |
| 时长 | **7.2s**（目标 5–8s，落在区间内） |
| 冷却 | 独立且更长，与无明一刻互不占用 |
| 槽位 | **Signature**，不是 Ultimate |

**关键裁决**：聚合斩是"这一招本身即演出"，无明一刻是"一次拔刀产生多个结果"。
两者共享风格（蓝 / 玻璃 / 世界切割），但**不共享资产**，也**不互相顶替槽位**。
通用层 `ultimate_id` 为空、藏锋流持有 `moment_of_no_moon` —— 数据结构上就把"大招属于流派"钉死了。

## 12. 无明一刻 · Moment of No-Moon（ULTIMATE，独立原型）

### 演出序列（"一刀，多果"）

| 时刻 | 事件 |
| --- | --- |
| 0.00 | 启动 |
| 0.15 | **声音消失** |
| 0.35 | 画面近乎单色（`set_world_drain`） |
| 0.95 | 有效敌人身上出现**极细白线标记** |
| 1.55 | 就位 |
| 2.00 → 2.09 | **一次几乎看不见的拔刀**（≤0.15s） |
| 3.10 → 3.85 | 纳刀 |
| 3.92 | **CLICK** |
| 3.99 | 全部标记**同时**激活 |
| 4.35 | 恢复 |
| 4.85 | 结束 |

**绝对不做 20 次瞬移斩。** 玩家看到的应该是"什么都没发生" —— 然后 "咔嚓" 一声，全场同时开花。

### 目标收集

| 参数 | 值 |
| --- | --- |
| 前向范围 | 16.0m |
| 锥角 | 70° |
| 上限 | **5** |
| 条件 | 范围 + 屏幕可见 + 视线无阻挡 |
| 单标记伤害 / 姿势 | 82.0 / 120.0 |
| 冷却 | 26.0s |

**优先级：Spectacle + Execution > 数值。**
高伤害、极高姿势伤害是结果，不是卖点；卖点是那 1 秒的静默和那一声 CLICK。

### 动画钩子（全新资产，不碰聚合斩）

`UltimateReady` / `UltimateDraw` / `UltimateHold` / `UltimateSheathe`
—— 详见 `docs/COMBAT_ANIMATION_REQUIREMENTS.md`。

## 13. 打击感：数值表

命中反馈 = **敌人反应 + 武器停顿/跟随 + 相机冲量 + hitstop + 声音 + 小 VFX**。六项都要有。

| 情境 | hitstop |
| --- | --- |
| 轻击 | **20–35ms** |
| 重击 | **45–70ms** |
| 完美格挡 | **50–80ms** |

**不要过量。** 工程师注意事项：`TimeEffectManager.request_hitstop()` 是**全局** `Engine.time_scale` 降到 0.05，
不是 per-hit 的。所以额外加了 `hitstop_scale` 作为乘数，并提供 **Off / Normal / Exaggerated** 三档预设
（开发面板可切换）—— 一个只吃单次命中停顿的系统不能靠全局时间缩放来表达风格差异。

## 14. 敌人：Technical Dummy 的职责是"服务剑的测试"

Dummy 不是展示对象，是**测量仪器**。它必须让玩家能练到每一件事：

| 它的动作 | 用来测什么 |
| --- | --- |
| Sweep | → 闪避 |
| Charged Heavy | → 完美格挡 |
| Lunge | → 站位 |

- 电报环（`TorusMesh` 向身体收缩）在**生效帧猝然闭合**，并伴随 `attack_phase_changed` 信号。
- 供给开发/测试的 API：`force_attack(variant)`、`attack_phase()`、`attack_phase_progress()`、
  `is_telegraphing()`、`is_striking()`、`on_interrupted(stagger)`。
- 攻击 poise：sweep 12 / heavy 40 / lunge 18 —— 重击能打断玩家，所以"必须挡"这件事是真的。
- **可读性目标**：玩家应该是在"读格挡时机"，而不是"背时间表"。
  配合开发者模式的 **Parry Timing Debug**（敌人阶段 + 完美格挡窗口余量实时显示）来验证这一点。

## 15. 开发者面板 · Combat Lab（F8）

面板不是一个菜单，是一件**乐器**：任意一行必须能在几秒内与任意一列相交，
否则"3 × 3 的倾向"只能靠嘴讨论，不能靠手感发现。

| 区块 | 内容 | 对应的列 / 行 |
| --- | --- | --- |
| 流派 | 四个流派按钮（`all_styles()`：通用 / 藏锋 / 回风 / 白蔷） | 行 |
| 技能 | 三个技能按钮，实时显示冷却余量 | 行 |
| 演出 | 触发聚合斩（Signature）/ 无明一刻（Ultimate） | 行 |
| **魔法** | 三系学派选择、当前学派法术选择、快速施法、风扩散 | **列** |
| 敌人 | 重置、强制攻击（Sweep / Heavy / Lunge）、冻结、生成 | — |
| **敌人状态** | 正常 / 燃烧 / 结霜 / 冻结，外加 Shatter 与 Brittle Break 一键铺垫 | **列 × 行** |
| **环境** | 就位到撞墙测试点、复位风场轻物；显示墙体位置与"轻物是否在动" | **列（风）** |
| 便利 | 重置技能冷却 / 重置行动 / 重置大招 FX / 慢动作 | — |
| 资源 | 无限 HP / Mana / Stamina | — |
| 反馈 | Hitstop 三档循环、相机预设循环、Parry Timing Debug | — |
| 保留 | 原有签名时间轴 scrub（STAGES / SPEEDS） | — |

两条纪律：

1. **面板的预设必须走真实路径。** 敌人状态按钮不是直接赋值，而是送进 `_on_hit` ——
   一个绕开机器的 Lab 捷径会让"面板上好看的组合"在实战里失效。
2. **读盘必须报出新系统。** 流派行显示 `势=NN%`（回风）或 `距离=x.xxm/ideal`（白蔷），
   魔法区显示学派 / 法术 / 剑上附魔，敌人区显示三系数值与 `brittle`，环境区显示墙位与撞击强度。
   `combat_lab_integration` 会断言这四块读盘不是空的。

## 16. 输入

沿用既有绑定，**不引入格斗游戏式输入**。

| 输入 | 动作 |
| --- | --- |
| LMB | 轻击 |
| RMB | 防御 |
| F | 重击（Tap / Hold） |
| Shift | 冲刺 |
| 1 / 2 / 3 | 流派技能 1 / 2 / 3 |
| X | 大招 |

### 魔法输入：单手剑不消失

主手永远是剑，副手施法。第一人称下**不能每次施法都把剑变没**。

| 类型 | 表现 | 例 |
| --- | --- | --- |
| **Quick Magic** | 剑留在主手，另一只手快速出手 | 火种 / 风压 / 冰爆 |
| **Heavy Magic** | 允许整段 Cast Pose | 焚环（地面火场） |

能力轮盘仍是 `Hold Tab + Drag + Release`，但它选的是**当前法术**，不是开一次菜单；
选定后由专门的魔法输入在战斗中快速放出（`select_school` → `spell_id` → `request(&"cast")`）。

`request()` 的优先级：**缠剑出口 > Riposte 窗口 > follow-up 窗口 > IDLE/取消 > 缓冲**。
`iaido` 与 `ultimate` **不入缓冲**，直接丢弃 —— 演出类动作被缓冲会在错误时机回放。

## 18. 设计问题（# DESIGN QUESTION，不阻塞开发）

1. **Measure 要不要一点可见反馈？** 当前完全无 UI，只靠手感与 `debug_state_line()`。
   流派承诺"主动控制距离"，但如果玩家看不见自己在哪一档，"主动"就没有抓手。
   倾向：不做资源条（那会把距离变成第二条血），但考虑一个极轻的脚步/呼吸提示。
2. **火需要敌人的"恐慌"行为，而 Dummy 目前没有行为分支。**
   要不要为它做**最小**的逃跑行为（`panic_health_fraction` 之下后退），
   还是先把火的价值压在"蔓延 + 烧退冰"上？
3. **白蔷庭该不该有 signature / ultimate？** 先证明 Measure，还是先给一个大招把流派"补完整"？
   这一轮选了前者。
4. **第四剑术 坠星式 是否真的需要？** 如果藏锋已经覆盖了"重"的位置，
   再多一个重的流派就是第四种换皮（见 §10）。
5. **无明一刻的目标上限 5 是否太低？** 上限低保证"每一个标记都被看见"，
   但清场效率会显得弱。这是一个"演出 vs 实用"的取舍，倾向保演出。
6. **回风式的大招（长风万里）是否需要一个"位移即伤害"的机制？**
   若做，它会与闪避系统争夺语义。
